# DecisionLab

Интерактивный веб-квест о расследовании утечки данных в университете. Игрок изучает материалы, сопоставляет устройства и задания, проверяет алиби и выносит вердикт. Приложение работает без внешних сервисов; Supabase и OpenRouter подключаются отдельно.

## Возможности

- Новые локальные сценарии четырёх типов, генерация ИИ и сохранённое резервное дело «Ночной экспорт».
- Подробные обстоятельства, 2–3 подозреваемых, 6–8 материалов четырёх типов.
- Серверный прогресс: изученные материалы, подсказки, попытки, время и очки.
- Восстановление текущего прохождения после обновления страницы и перезапуска локального сервера.
- Доска улик: поиск по содержимому, фильтры, сортировка и связи по общим идентификаторам. Связи являются направлениями проверки, а не автоматическим доказательством виновности.
- Подтверждение обвинения, отдельные сообщения для неверного, повторного и просроченного вердикта.
- Итоговый разбор, формула очков и полнота исследования.
- Повторное прохождение, история и статистика последних 100 раскрытых дел этого браузера.
- Страница `/api-test`: редактор JSON, реальные ID, HTTP-статус, время запроса, копирование, очистка и история запросов.
- OpenAPI 3.1: `/openapi.json`; подробная документация: [docs/API.md](docs/API.md).

## Стек и архитектура

Next.js 16.3, React 19, TypeScript, Tailwind CSS 4, Zustand, Supabase, OpenRouter. Используется App Router; логика приложения не требует отдельного backend-проекта.

1. `app/page.tsx` читает HttpOnly-cookie и восстанавливает текущую сессию. При первом посещении создаёт локальный сценарий.
2. `app/case-client.tsx` управляет расследованием. Компоненты материалов, доски и результата вынесены в `app/case-panels.tsx`, `app/evidence-board.tsx`, `app/session-result.tsx`.
3. `lib/game-store.ts` хранит подтверждённый сервером снимок. Запоздавший ответ не может заменить более новую версию состояния.
4. Route Handlers используют `lib/api.server.ts` для envelope, ошибок, cookie и валидации входа. `lib/api-client.ts` переводит ошибки в понятные сообщения.
5. `lib/game-session.server.ts` проверяет принадлежность улик и подозреваемых, срок сессии, повторные подсказки/попытки и рассчитывает результат.
6. `lib/generate-case.server.ts` вызывает ИИ, проверяет результат и сохраняет дело. `lib/local-case-generator.server.ts` и неизменённый `lib/fallback-case.json` позволяют работать без ИИ.
7. Сессии дел из Supabase хранятся в Supabase. Локальные дела и сессии сохраняются атомарной заменой JSON в `.decisionlab/data.json`.

Правильный ответ доступен только серверу. Публичные пакеты проходят явный список разрешённых полей в `lib/public-case.ts`. Поле `hint` в публичном материале пустое; текст открытой подсказки возвращается после серверного учёта. Разбор появляется только после верного вердикта. Неверный вердикт не раскрывает правильного подозреваемого.

## Запуск

Используйте Node.js 22+; проверки проекта выполнялись на Node.js 24.21.

```bash
npm ci
npm run dev
```

Игра: `http://localhost:3000`; консоль: `http://localhost:3000/api-test`.

Без `.env.local` доступны локальные сценарии и резервное дело. «Новое дело» меняет сценарий; «Заново» обнуляет прохождение того же дела. Обновление страницы сохраняет текущий прогресс — это намеренно изменённое поведение по сравнению с прежней версией.

## Переменные окружения

Скопируйте `.env.example` в `.env.local` или `.env` и заполните только необходимые значения. Next.js читает оба файла; если одна переменная задана в обоих, `.env.local` имеет приоритет.

| Переменная | Назначение |
| --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | URL проекта Supabase |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | Публичный ключ вспомогательных клиентов; игровой API использует серверный клиент |
| `SUPABASE_SERVICE_ROLE_KEY` | Серверный ключ базы; никогда не добавлять префикс `NEXT_PUBLIC` |
| `OPENROUTER_API_KEY` | Серверный ключ OpenRouter |
| `OPENROUTER_MODEL` | Модель; значение по умолчанию в коде: `google/gemma-4-26b-a4b-it:free` |
| `DECISIONLAB_DATA_DIR` | Каталог локальных данных; по умолчанию `.decisionlab` в корне проекта |
| `TEST_BASE_URL` | Адрес сервера для HTTP-тестов; по умолчанию `http://localhost:3000` |

Ключи, локальное хранилище и временные тестовые данные исключены из Git. Доступность модели и её условия зависят от провайдера; задайте подходящую модель своего аккаунта. После изменения переменных перезапустите сервер.

## Supabase

Примените SQL через Supabase SQL Editor от роли postgres, строго по порядку:

1. `supabase/migrations/202609150001_initial_case_schema.sql`
2. `supabase/migrations/202609260001_create_case_rpc.sql`
3. `supabase/migrations/202609270001_investigation_progress.sql`

Первая миграция создаёт `cases`, `suspects`, `evidence`, `sessions`, `attempts`, ограничения связей и RLS. Вторая — атомарное создание дела. Третья добавляет анонимного владельца, JSON-состояние, версию сессии и индекс истории; закрывает прямое чтение подсказок; добавляет серверный RPC с блокировкой строки и проверкой версии. Старые миграции не изменялись.

До установки третьей миграции обновлённые сессии Supabase работать не будут. Приложение не применяет миграции автоматически. Подробности и SQL-проверки: [supabase/README.md](supabase/README.md).

## Генерация ИИ

Режимы `POST /api/case/generate`:

- `auto`: ИИ при наличии ключа; при ошибке после двух попыток — новый локальный сценарий.
- `ai`: только ИИ; после двух неудачных попыток — `503` и выбор повторить/использовать резервное в UI.
- `local`: новый локальный сценарий без запроса к ИИ.
- `fallback`: исходное дело «Ночной экспорт» с новым ID прохождения.

Каждый запрос ИИ ограничен 25 секундами. При HTTP 429, 401/403, 402 или 404 повтор сразу не выполняется: API объясняет ограничение, отказ доступа, баланс или отсутствие модели. До сохранения проверяются структура, допустимые поля, уникальность подозреваемых и материалов, диапазон ответа, покрытие типов и разделов, независимые технические улики, альтернативный след, явные маркеры ответа и порядок отметок времени в журналах. Невалидный результат не сохраняется. Повторный запрос получает новый идентификатор.

В серверные логи записываются эвристики качества: покрытие, баланс описаний, порядок журналов, отсутствие прямых подсказок-ответов. Эти проверки **не доказывают логическую непротиворечивость всего сюжета**. Для публичной демонстрации конкретное дело полезно предварительно просмотреть. Исходные материалы и имена участников вымышлены.

Если запись в базу недоступна, полученное дело сохраняется локально; оно не подменяется одним статичным сценарием. Неудача существующей сессии Supabase не создаёт молча новую сессию: API возвращает `DATABASE_UNAVAILABLE`.

## Правила счёта

```text
100 − 10 × подсказки − floor(секунды / 30) − 5 × неверные обвинения
```

Минимум — 0, длительность — 30 минут. Сервер определяет время и итог. Повторный запрос одной подсказки бесплатен. Одного подозреваемого можно обвинить один раз за прохождение. После верного ответа время и счёт фиксируются. Полнота исследования — процент открытых материалов; дополнительных штрафов за неё нет.

## API

| Method | Endpoint | Назначение |
| --- | --- | --- |
| GET | `/api/health` | Состояние приложения, базы и конфигурации ИИ |
| GET | `/api/case` | Публичные материалы текущего дела или `?caseId=UUID` |
| GET / POST | `/api/case/session` | Получить состояние / начать или восстановить прохождение |
| POST | `/api/case/evidence` | Сохранить изучение материала |
| POST | `/api/case/hint` | Открыть подсказку |
| POST | `/api/case/verdict` | Проверить обвинение |
| GET | `/api/case/progress` | Прогресс в целом и по разделам |
| POST | `/api/case/restart` | Повторное прохождение |
| POST | `/api/case/generate` | Создать дело |
| GET | `/api/history` | Последние 100 завершённых прохождений |
| GET | `/api/statistics` | Статистика этих прохождений |

Все обработчики возвращают `{ success, data, message }` или `{ success: false, error: { code, message, details? } }`. Тексты ошибок не содержат stack trace, ключей или правильного ответа. OpenAPI — статический JSON-файл, пригодный для импорта в Swagger/Postman. После изменения контракта выполните `npm run docs:api`.

## Проверки

```bash
npm run typecheck
npm run lint
npm test
node scripts/validate-fallback.mjs
npm run build
```

При запущенном сервере:

```bash
npm run test:api
```

Unit-тесты используют отдельный каталог `.test-data`, подменяют ответы OpenRouter и не расходуют токены. Проверяют разнообразие сценариев, скрытие ответа/подсказок, прогресс, одновременные запросы подсказки, изоляцию посетителей, повторы, истечение сессии, формулу очков, историю и валидацию ИИ. HTTP-тесты создают собственного анонимного посетителя и проверяют все 12 операций, ошибки, восстановление, restart и fallback. Их прохождения остаются в локальной базе как тестовые данные отдельного посетителя.

SQL-тесты запускаются отдельно в подготовленной PostgreSQL-базе; оба файла делают `ROLLBACK`. Supabase в среде проверки не настроен. После добавления ключа в `.env` выполнен реальный запрос OpenRouter: сервис вернул HTTP 429 (ограничение запросов). Успешная живая генерация поэтому пока не подтверждена; сценарии успешного ответа, невалидного JSON, повторов и ограничений проверены с подменой ответов.

Ручная проверка UI: ширины 375, 768 и 1440 px; меню, модальные окна, длинные журналы, поиск, подтверждение, результат и API Tester. Проверить Tab, Shift+Tab, Escape и возвращение фокуса. Native `<dialog>` обеспечивает модальный фокус. Автоматизированный визуальный прогон требует доступного браузера.

## Демонстрация

1. Откройте игру, дождитесь создания сессии.
2. Создайте новое локальное дело через «Новое дело».
3. Откройте материалы в нескольких разделах; проверьте счётчики и доску.
4. Используйте подсказку и откройте её повторно — второй раз очки не списываются.
5. Обновите страницу: дело и прогресс сохраняются.
6. Откройте `/api-test`, отправьте GET case, session, progress и health. Для POST выберите реальные ID из блока загруженного дела.
7. Вернитесь в игру, выберите участника и подтвердите вердикт.
8. После успеха просмотрите расчёт счёта и разбор, затем историю.
9. Нажмите «Пройти ещё раз»: прогресс обнулится, предыдущий результат останется.

## Deployment и ограничения

```bash
npm run build
npm run start
```

Базовый вариант размещения — один Node.js-процесс на сервере с постоянным записываемым томом для `DECISIONLAB_DATA_DIR`, HTTPS и заполненными переменными окружения. Cookie в production имеют флаг Secure. Next.js загружает Geist при сборке, поэтому сборщику нужен доступ к Google Fonts либо заранее подготовленный кэш.

Локальное JSON-хранилище рассчитано на один процесс и небольшие демонстрации. Не используйте его одновременно из нескольких процессов; храните резервную копию каталога и не публикуйте его как статику. Обычный serverless с временной/доступной только для чтения файловой системой **не подходит для локального режима текущей версии**. Для горизонтального масштабирования необходимо перенести также первоначальные и аварийные локальные дела в общее хранилище. Сами сессии Supabase уже используют атомарную запись с контролем версии.

Анонимная история привязана к cookie, не является аккаунтом и не переносится между устройствами. Удаление cookie лишает браузер доступа к прежней истории. Это учебный продукт: нет регистрации, панели администратора с ответами и ограничений публичной генерации на уровне шлюза; перед открытым интернет-размещением настройте доступ к демонстрации и лимиты запросов на инфраструктуре.
